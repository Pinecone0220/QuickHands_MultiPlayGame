# 팔면체 주사위 검증

Unity6000.3.18f1 / NGO2.13.3 / 프로토콜43 / Windows 개발 빌드.

규칙52개, 실제 루프백 호스트22개·원격 플레이어21개·대기자17개, 실행본 렌더2개를 통과했다. 전용 서버/실제 인터넷 지연·손실 조건은 이번 검증에 포함하지 않았다.

기존 아이템 선택/준비 취소·재준비/완전 탈락 관전·최종 결과 고정/전원 준비 후1인칭 재경기는 규칙47개·호스트39개·원격45개·늦은 참가35개, 총166개 회귀 검사도 통과했다. 전체 검증은280개다. 빌드와 제작 소스/셰이더/스타일 해시가 일치함을 확인했다.

규칙 검증은1~8 눈/한 번만 확정/대상 외 좌석/이전 경기·iteration·굴림 nonce/마감 경계/10초 자동 확정/같은 눈 재굴림/서로 다른 원래 기록 그룹 보존/이탈자 제거를 포함한다. 초읽기·신호등·욕심의 대가의 동점, 뭐였더라?의 오입력 그룹·이전 라운드 탈락 순위 보존, 퀵핸즈 동시 사망 그룹/목숨0 대상·마지막 생존자 이탈/최종 승리 보류, AI 자동 정지·통계 중복 방지와6좌석 스냅샷 직렬화·동등성을 검사했다.

원격 검증은 세 개의 독립 Windows 프로세스를 사용했다. 첫 판은 초읽기 기록이 같은 호스트/클라이언트가 실제 SPACE 입력→소유자 RPC로 확정하고 비해당 원격 화면이 같은 눈/순위를 받는지 검사했다. 채팅을 연 상태의SPACE는 확정하지 않았고 오래된 경기/등록되지 않은 발신자 요청도 거절했다. 다음 판은 퀵핸즈의 같은 배치 사망자2명 중 한 명을 목숨0, 다른 한 명을 목숨2로 두고 두 소유자 모두 SPACE로 자기 주사위만 확정하는지 검사했다. 주사위는 추가 목숨 차감을 만들지 않았고 기존 사망 순서/생존자 순위를 보존했다.

렌더는 숫자8이 앞에 보이는 확정 자세와 숫자 면이 회전하는 모습을 실행본에서 캡처했다. 숫자용 깊이 판정 셰이더로 뒷면 글자가 앞면에 비치지 않게 했고 메뉴에서 미리 렌더링해 첫 굴림의 준비 지연을 줄였다. 이미지: `Docs/Previews/Dice-Rolling.png`, `Docs/Previews/Dice-Stopped-8.png`.

재현 도구는 Tools/UnityQA/DiceRuntimeQA.cs다. 제작 프로젝트Assets에는 넣지 않고 격리 QA 프로젝트에서 `--dice-qa model/host/client/observer/preview/review`, `--dice-dir`로 실행한다. 도구에서 순위/동시 사망을 만들기 위한 기록·체력/목숨 조절은 검증 환경에만 있으며 제품의 관리 API/RPC로 노출하지 않았다.

## 표시 순서·제목 후속 수정

빈자리/닉네임/상태/목숨 레이어를 다른 게임 UI 뒤로 이동하고 주사위 패널 배경을 불투명하게 해 글자가 비치지 않도록 했다. 굴리기/비교/재굴림 제목은 주사위 겨루기로 통일했다. 격리 Unity 에디터에서 변경 소스의 컴파일과 기존 preview 2개 검사를 통과하고 확정 화면의 겹침 해소를 확인했다. 위 미리보기 이미지를 교체했으며 이번 UI 수정에 Windows 빌드/네트워크 전체 검사를 반복하지는 않았다. 프로토콜43과 게임 규칙은 유지한다.
