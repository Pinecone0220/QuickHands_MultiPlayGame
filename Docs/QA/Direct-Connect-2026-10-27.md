# 직접 접속 복원 검증

- 대상: Unity 6000.3.18f1 / NGO 2.13.3 / 프로토콜60 / Windows Development 빌드, `QuickHands.unity`.
- 호스트 IP(127.0.0.1)·포트(7777), 방 만들기/참가하기를 복원했다. 실행 경로에서 방 검색·광고·코드/비밀번호 승인을 제거했다. 기존 검색 유틸리티 소스는 호출하지 않는다.
- 승인 데이터는 정규화한 UTF-8 닉네임이다. 서버의 6인 정원·봇/승인 예약 포함·게임 진행 중 참가 제한을 유지했다.
- 최근 총기/아이템/카메라/Alt 조작과 패치노트 기능은 유지했다. 오늘 날짜의 접속 방식 복원 내역을 패치노트에 추가했다.

## 확인 결과

`Tools/UnityQA/DirectConnectRuntimeQA.cs`: 실제 호스트 24개·원격 클라이언트 18개 검사 통과.

- IP·포트 기본값과 버튼, 목록/코드/비밀번호 UI 부재, 잘못된 IP/포트 거절.
- 검색용 UDP 47770~47785를 모두 점유해도 직접 방 생성·참가 성공.
- 게임 포트18911 점유 시18912로 대체하고 실제 포트 표시. 두 번째 방은 지정한18913 사용.
- 한글 닉네임 양방향 전달, 좌석 배정, HP100/목숨3 초기 스냅샷.
- 새 참가자 입장 시 방장의 준비 상태 유지, 두 명 모두 준비하면 시작.
- 방장 퇴장 후 클라이언트 연결 정리, 같은 실행 프로세스에서 두 번째 방 재생성/재접속, 준비/선택 확정 상태 초기화.
- `Tools/Test-TaserHitscan.ps1`: 기존 게임 로직 82개 검사 통과.
- `Tools/UnityQA/PatchNotesRuntimeQA.cs`: 시작 자동 표시·누적 4개 패치 항목·닫기/재열기·로비 진입 등 14개 검사 통과.
- Windows 최종 빌드 성공. 직접 접속 메뉴 스크린샷: [화면](../Previews/Direct-Connect-2026-10-27.png).

검증은 같은 PC의 두 독립 실행 파일에서 수행했다. 별도 PC 사이의 실제 공유기/방화벽 환경은 이 검사 범위에 포함하지 않는다. 참가자는 방장의 LAN IP와 로비에 표시된 실제 포트를 사용한다.
