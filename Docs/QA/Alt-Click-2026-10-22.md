# Alt 커서는 보이지만 클릭이 되지 않는 문제 수정

2026-10-22 / Unity6000.3.18f1 / 로컬 UI 수정 / 프로토콜48 유지.

원인: Unity Clickable의 기본 활성화 필터는 수정키 없는 좌클릭만 받는다. 루트의 입력 차단을 통과해도 실제 Button.clicked와 Toggle의 클릭 처리는 Alt 수정키 때문에 시작되지 않았다. [Unity6000.3 활성화 필터 구현](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Modules/UIElements/Core/ManipulatorActivationFilter.cs)과 [Clickable 구현](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Modules/UIElements/Core/Clickable.cs)을 확인했다.

- 공통 버튼 생성 시 Alt 좌클릭 필터를 추가했다. 기존 메뉴의 일반 클릭도 유지한다.
- 방 설정 토글에는 Alt 전용 Clickable을 추가했다. 값 변경 이벤트는 기존 서버 요청 경로를 그대로 사용한다.
- 누르는 도중 Alt를 놓으면 포인터 캡처를 해제해 클릭을 취소하고 다음 조작을 막지 않게 했다.
- 네트워크 메시지/서버 권한/사격 규칙은 변경하지 않았다.

`Tools/UnityQA/AltClickRuntimeQA.cs`는 ClickEvent를 직접 보내는 대신 실제 UI 요소에 Alt 수정키가 든 PointerDown/PointerUp을 전달한다. 수정 전에는 일반 메뉴 버튼은 성공했으나 Alt 무기 선택이 실패해 문제를 재현했다. 수정 후 Unity 컴파일 및 그래픽 실행28개 검사가 통과했다.

확인 범위: 메뉴 열기/닫기, 좌/우 Alt 무기 선택, Alt 없는 클릭 차단, 시작 아이템 선택, 준비 완료/취소, 방 설정 토글 반복, 클릭 도중 Alt 해제 후 정상 재클릭, 응급 앰플 버튼의 실제 회복/소비, Alt 해제 후 게임 조작 복귀. UI 레이아웃 갱신을 기다린 뒤 각 버튼을 클릭한다.

증거: `%TEMP%/RouletteQA-bb1739d9/AltClickBefore/done`의 재현 실패와 `AltClickFinal/done`의 `PASS Alt click: 28 checks`, `alt-click-before.log`, `alt-click-final.log`. 기존 LAN 검사의 단순 ClickEvent 통과/직접 아이템 요청은 실제 버튼 활성화 검증을 대체하지 못했으며 이번 검사가 이를 보완한다.
