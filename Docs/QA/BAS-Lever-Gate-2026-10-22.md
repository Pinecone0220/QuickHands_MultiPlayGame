# BAS 발사 후 ADS 잠금 / 연습 레버 입력

BAS 발사 요청 직후 로컬 ADS를 해제하고 응답 대기 중 재조준을 막는다. 서버는 본 경기와 준비 연습에서 레버 액션 중 ADS/발사를 거절한다. 실제 잔탄이 있어도 우회하지 못한다. 본 경기 레버/장전/닫기 흐름은 유지하며, 무한 예비 탄약을 사용하는 준비 연습은 매 발사마다4자리 레버 입력으로 Aim에 복귀한다. 준비 취소/재준비에는 초기화한다.

연습 입력창/입력 예측/오입력 대기/완료 효과음/탄피 배출도 지원한다. 연습 입력은 실제 경기 입력·오입력·킬·피해 통계와 결과를 바꾸지 않는다. 프로토콜47이며 네트워크 필드/RPC 서명 추가는 없다. 흔들림 자체는 변경하지 않았다.

검증:

- `Tools/Test-BasWeapons.ps1`:675개 통과. 탄이 있는 레버 단계에서도 조준/발사를 거절하고, 매 연습 발사 뒤4자리 조작을 요구하며 실제 경기 기록을 보존한다. 기존 피해/목숨/탄도/재장전 검사도 유지한다.
- Windows Development 빌드 성공. 실제3개 프로세스에서 호스트11/클라이언트16/관전자11개 통과. 원격 Owner Input RPC로 레버를 완료한 뒤 다시 발사하고, 모든 화면에서 ADS 잠금 액션을 공유한다.
- Unity 그래픽 실행43개 통과. Owner Fire/Look 요청 뒤 스코프 해제/잠금, 실제 UI Press 콜백으로4자리 완료/재조준 허용, 레버/탄피/음원/스코프를 확인했다.
- 기존 슬롯 재사용5개 회귀 통과.

이 배치 환경에서는 자동 마우스 이벤트 주입이 버튼 down을 전달하지 못했다. 해당 자동 주입 검사는 최종 검사에서 제외하고 Owner RPC·UI 콜백·실제 렌더를 사용했다. 로컬 발사 즉시 해제/pending 분기는 코드 검토했으며, 실제 하드웨어 마우스의 체감·WAN 지연은 확인하지 않았다.
