# 테이저/개발용 전체 아이템 선택 검증

- Unity6000.3.18f1 / NGO2.13.3 / Windows 개발 빌드 / 프로토콜42.
- 격리 QA 프로젝트에서 규칙19개, 실제 루프백 호스트28개·원격 사격자25개·늦은 참가 제3자17개, 총89개 통과.
- 기존 LoadoutRuntimeQA 규칙47개·호스트38개·원격39개·늦은 참가34개, 총158개 회귀 검사 통과.

서버 개발 설정으로 현재 전원과 나중에 들어온 좌석의 아이템 선택이 채워지는지, 대기 중 지급은 없는지, 준비 유지/F11 옵션 초기화/경기 중 변경 거절/스냅샷 직렬화·동등성을 확인했다. 사람의 일반 수동 선택과 첫 시작 확정/재경기 지급도 유지된다.

테이저 사용N 후 N+1/N+2 거절과 N+3 허용, 무한 아이템의 쿨다운 면제와 퀵핸즈 금지 유지를 확인했다. 원격 소유자 RPC로 활성화/발사하고 실제 서버 투사체로 상대에게5 피해를 주었다. 세 화면에서 체력95·감전·비치명 로그/테이저 아이콘이 일치했고, 피해자1인칭은 전기 아크를 숨기고 다른 두 화면에서는3개 아크가 표시됐다. 사격 종료 뒤 상태/아크가 모두 사라졌다.

두 번째 사격은 대상의 시험 체력을5로 두고 실제 테이저 탄환으로 처치했다. 전원에게 테이저 처치 로그가1개씩 전달됐고 비치명 감전 표시는 중복되지 않았다. 남은 목숨3→2와 피해자 목숨 차감 안내도 확인했다. 시험 체력/순위/카운터 조절은 QA 도구 안에서만 사용하며 제품 코드에는 없다.

렌더는 Unity 에디터의 별도 미리보기와 URP 렌더 요청으로 확인한다. 실행본의 화면 캡처 API는 batchmode에서 지원되지 않아 행동 검증과 렌더 캡처를 분리했다. 전용 서버와 실제 인터넷 지연/손실 조건은 이번 범위에 포함하지 않았다.

재현: Tools/UnityQA/TaserRuntimeQA.cs(`--taser-qa model/host/client/observer/preview`, `--taser-dir`), Tools/UnityQA/LoadoutRuntimeQA.cs. 두 도구는 제작 프로젝트 Assets에 넣지 않고 격리 QA 프로젝트에서만 실행한다.
