# 시선 제한·사격 보정 방지 검증

Unity6000.3.18f1 / NGO2.13.3 / 프로토콜43 유지. 정면 기준 마우스 좌우±85도, 기존 상하±65도다.

Windows 개발 빌드 성공. 규칙115개·독립 호스트6개·원격7개, 총128개 검사 통과.

- 6개 좌석에서 큰 양/음 마우스 이동이 반대쪽으로 감기지 않고 올바른 끝각도에 멈추며, 반대 입력에 즉시 반응한다.
- 양옆 플레이어 머리 방향에 최소15도 이상의 추가 조준 공간이 있고, 끝각도의 실제 광선은 플레이어를 맞히지 않는다.
- 서버가 뒤쪽 시선/범위 밖 자발적 사격 요청을 거절하고 각도·Version·탄약·발사 횟수를 변경하지 않는다.
- 좌석0/5의 양끝각도에서 리볼버/소드오프, 일반/정조준 사격을 검사했다. 원본 각도가85도여도 흔들림으로 실제 발사각이 경계를 넘어가며, 원래 탄 퍼짐과 수직 흔들림도 그대로 적용된다.
- 실제 호스트·원격의 MouseState 입력으로 양쪽 제한과 즉시 반전을 확인했다. 원격의 범위 밖 사격은 탄을 소비하지 않았고, 허용 끝각도의 사격은 한 발을 소비해 실제 투사체를 만들며 상대를 향해 보정되지 않았다.

제작 소스와 격리 QA 소스의 관련 파일 해시가 일치한다. 감전의 서버 내부 강제 시선/격발 예외와 고정 관전/최종 결과 카메라 경로는 변경하지 않았다. 전용 서버/실제 인터넷 지연·손실 실기동은 이번 범위에 포함하지 않았다.

재현: Tools/UnityQA/LookLimitRuntimeQA.cs를 격리 QA 프로젝트에서만 사용한다. `--look-limit-qa model/host/client --look-limit-dir <공유 새 결과 폴더>`를 각 실행본에 전달한다. 테스트의 단계/무기 준비 조작은 제품RPC에 추가하지 않는다.
