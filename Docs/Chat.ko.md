# 방 채팅

2026-10-20. 로비에 참가한 뒤부터 AI/PvP, 미니게임, 아이템 사용, 사격, 사망/관전, 결과 화면에서 사용한다. 메인 화면과 접속 대기 중에는 숨긴다.

## 조작과 표시

- Enter/숫자패드 Enter: 채팅 입력 활성화. 입력 중 다시 누르면 전송 후 비활성화한다. 빈 입력은 닫는다.
- 열자마자 텍스트 편집 요소에 포커스를 두므로 마우스로 입력칸을 다시 누를 필요가 없다. 커서 위치는 Unity 편집기가 관리하며 조합 미리보기 길이로 강제로 옮기지 않는다.
- Esc 또는 채팅 바깥 화면 클릭: 비활성화하고 게임 조작으로 복귀한다. 닫는 클릭 자체로 사격하거나 뒤쪽 UI를 누르지 않는다.
- 활성화 중에는 휠로 대화 기록을 스크롤한다. 마우스가 채팅 영역 밖에 있어도 휠로 기록을 넘길 수 있다.
- 과거 대화를 읽는 중 새 메시지가 와도 맨 아래로 강제로 이동하지 않는다. 비활성화하면 최신 대화를 보여준다.
- 채팅 레이어는 결과/아이템 패널보다 앞에 유지한다. 입력 중에는 마우스 잠금을 풀고 숫자·방향·정지·사격·조준·F11 입력을 차단한다. 서버의 미니게임/사격 제한시간은 계속 진행한다.
- 한글 조합 중 Enter를 누르면 전송 요청을 유지하고 조합 확정/마지막 글자 반영을 기다려 한 번 전송한다. 조합 종료와 본문 변경 후 최소2프레임/50ms 안정 대기를 사용한다. 빠른 연속 전송도0.75초 제한이 끝날 때까지 요청을 유지하며 Esc/바깥 클릭은 대기 요청을 취소한다.
- 채팅 활성화마다 TextField/TextElement를 새로 생성한다. 초안만 문자열로 보관하며 전송한 편집 버퍼는 비우거나 재사용하지 않는다. 포커스 시 네이티브 IME를 활성화하고 닫을 때 종료한다. 닫힌 동안 들어온 조합 이벤트는 무시하며 새 활성화에서 대기/조합 플래그를 초기화한다.

## 캐릭터 위 채팅

`DuelChat.Speech`는 기존 서버 확인 채팅의 발신자 OwnerClientId를 각 화면의 스폰된 Player/Seat에 연결한다. 닉네임 문자열이 같아도 발신자를 혼동하지 않는다. 캐릭터의 기존 이름표 기준 좌표를 따라 목숨/상태/이름 패널 위에 최대3개 메시지를 쌓는다. 본인 모델이 숨겨지는1인칭/화면 밖/빈 좌석에는 표시하지 않으며 기존 미니게임 패널 표시와는 별도 레이어다. 말풍선은 클릭을 가로채지 않고 rich text를 해석하지 않는다.

- 각 메시지는 수신 후3초 동안 완전한 불투명도로 유지한 뒤1초에 걸쳐 선형 페이드한다.1~2개는 각자 이 시간을 따른다.
- 3개가 쌓이면 가장 오래된 메시지만 페이드하고 나머지는 현재 투명도에서 기다린다. 앞 메시지가 사라지면 다음 메시지가 이어서 페이드하며, 대기열이 비면 다시1~2개 동시 페이드 방식으로 돌아간다.
- 대기 중인 메시지도 최초3초 유지 시간은 함께 흐른다. 자기 순서가 오면 유지 시간이 남은 경우만 기다리고 페이드한다.
- 4번째 메시지는 가장 오래된 항목을 밀어내 최근3개만 유지한다. 프레임이 늦어져도 만료 시각을 누적 처리하고 방을 나가면 비운다.
- 메시지 순서/중복 검사를 통과한 수신만 표시한다. 이미 받은 최신 기록보다 오래된 재전송은 대화 기록에는 추가하되 말풍선을 다시 띄우지 않는다.

`DuelSpeechQueue`는 로컬 표시 시간만 관리한다. 기존 reliable 채팅 RPC/권한/내용 검증/프로토콜39는 유지하며 서버 전용 ConnectedClients를 클라이언트 UI에서 사용하지 않는다. 좌석당3개 Label을 재사용한다.

2026-10-20 표시 크기/시간 조정: 말풍선 최대 폭280→340px, 글씨13→17px, 안쪽 여백5/9→8/12px로 확대했다. 기존 즉시5초 페이드를 위의3초 유지+1초 페이드로 대체했으며 순차 페이드/최대3개/4번째 교체 규칙은 유지한다.

## 서버와 기록

`HelloWorldPlayer.SendChatRpc`는 Owner 호출 권한과 실제 SenderClientId를 검사한다. `HelloWorldManager.RequestChat`은 등록/스폰/연결을 확인하고 닉네임을 서버 좌석 정보에서 가져온다. 사망 여부나 경기 단계는 채팅 권한을 제한하지 않는다.

`DuelChatLog`가 공백/제어문자를 정리하고 최대120개 텍스트 요소/UTF-8 480바이트로 제한한다. 본문은 FixedString512Bytes, 닉네임은 FixedString64Bytes로 전송하며, 서버는 발신자마다0.6초 간격을 검사한다. 클라이언트는0.75초 간격으로 과도한 연속 전송을 줄인다. 거절된 입력은 다음에 수정해 보낼 수 있도록 복원한다. 메시지 Label은 rich text를 해석하지 않는다.

서버는 순서를 부여해 각 플레이어 오브젝트의 Server→Owner reliable RPC로 전달한다. 호스트도 한 번만 수신한다. 수신자는 sequence로 중복과 순서를 정리한다. 서버/클라이언트 모두 최근100개를 보관하며 미니게임·재경기 동안 유지한다. 새 방 입장/퇴장 시 로컬 기록을 비운다. 늦은 참가자에게는 스폰 전송 뒤 다음 프레임에 기존 기록을 전달한다. 예전 닉네임은 발언 당시 값으로 보관한다.

## 입력 분리

`DuelChat`은 DefaultExecutionOrder(-200)으로 게임 입력보다 먼저 Enter/클릭을 확인한다. `BlocksGameplay`는 열린 동안과 열고 닫은 프레임에 참이다. `DuelFirstPerson`, `RouletteView.CanAct/IsMemoryTurn/StopClock` 및 F11 진입점이 이 값을 확인한다. 닫은 뒤 다음 프레임에 FPS 조작을 복귀시켜 닫는 클릭의 오발을 막는다.

UI 갱신은 계속 진행하며 채팅은 LateUpdate에서 맨 앞으로 올린다. UI root 이벤트는 채팅에 사용한 Enter/Esc와 바깥 클릭이 다른 버튼으로 전달되는 것을 막는다. IME 이벤트 구독과 root 콜백은 컴포넌트 종료 시 해제한다.

2026-10-20 입력 수정: RouletteView root에서 별도로 발생하는 NavigationSubmitEvent도 차단해 Enter가 이전에 선택된 준비/아이템/메뉴 UI를 실행하지 않게 한다. DuelChat은 TextField 바깥 요소 대신 실제 내부 TextElement를 즉시/레이아웃 반영 뒤 포커스하고 커서를 초안 끝에 둔다. 마우스 클릭과 기존 전송/IME 보호 규칙은 유지한다. Unity 6000.3의 [텍스트 필드 구현](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Modules/UIElements/Core/Controls/InputField/TextInputFieldBase.cs)을 확인했다.

2026-10-20 첫 글자/한글 입력 재수정: 물리 Enter와 별도로 전달되는 `KeyCode.None + '\r'/'\n'` 문자 이벤트도 차단한다. 기존에는 이 이벤트가 [KeyboardTextEditor의 줄바꿈 처리](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Modules/UIElements/Core/Controls/InputField/KeyboardTextEditor.cs)로 들어가 편집 포커스를 TextField 바깥으로 옮겼다. 편집 요소가 이미 포커스를 받았거나 IME 조합 중이면 예약된 포커스 처리는 커서를 다시 옮기지 않는다. 닫을 때도 실제 편집 요소의 포커스를 해제한다.

프로토콜39. 채팅 RPC 추가에 따른 호환성 번호이며 기존 경기 스냅샷/판정 규칙은 변경하지 않는다.

2026-10-20 한글 조합/전송 재수정: 실제 사용자 Editor.log에서 GeneratePreviewString/ReplaceSelection의 startIndex 범위 초과 예외가 반복되는 것을 확인했다. 조합 미리보기 길이로 cursorIndex/selectIndex를 쓰는 동작을 전부 없앴고, 전송 시 Blur로 내부 IME 저장 커서를 복원한 뒤 입력칸을 비운다. 문자 없는 물리 Enter는 원래 텍스트 편집기에 전달해 확정 처리를 허용하되 CR/LF는 계속 차단한다. Return 코드에 실린 유니코드 본문도 보존한다. 입력 본문은 화면의 input.text를 사용하며 전송 요청은 조합 종료와 별도 문자 이벤트가 반영될 때까지 폐기하지 않는다. 앞선 조합 확정 Enter의 전송 금지 규칙을 대체한다. 소스 근거: [TextEditingUtilities](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.3/Modules/IMGUI/TextEditingUtilities.cs).

## 검증

크기/3초 유지 조정: Unity 플레이에서3초 직전/경계의 불투명도1,3초 이후 페이드, 각 메시지의 독립 유지 시간,3개 순차 전환과 초기화, 새 글씨17px/폭340px 렌더 등27개 검사를 통과했다. 확대 화면도 위 미리보기 파일에 갱신했다. 네트워크/RPC는 변경하지 않았다.

캐릭터 위 채팅: Windows 개발 빌드 성공 후 페이드/3개 순차 대기/상한/장시간 프레임/중복·이전 기록/발신자별 분리/실제 위치와 클릭 통과/퇴장 정리23개, 별도 호스트13개·원격 참가12개·늦은 참가12개를 통과했다(총60개). 원격 클라이언트에서도3명의 Player 객체와 발신자 좌석 연결 및 마지막 원격 메시지의 별도 말풍선 대기열을 확인했다. [실행 화면](Previews/Chat-Speech.png). 로컬 루프백이며 인터넷 지연 환경은 포함하지 않는다.

연속 입력 최신 수정: 같은 편집기를 재사용하던 구조를 없앴다. 실제 사용자 최신 로그에 조합 커서 예외가 다시 남아 있었으며, 이전54개 검사는 Windows 네이티브 조합 버퍼를 생성하지 않아 이 실패를 검출하지 못했다. 새 입력칸에는 이전 TextEditingUtilities/미리보기/저장 커서가 연결되지 않는다. 초안은 포커스 전 새 버퍼에만 초기화하며, 전송/거절/퇴장 모두 이전 편집 버퍼를 직접 고치지 않는다. Keyboard.SetIMEEnabled의 [공식 IME API](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.14/manual/Keyboard.html#ime)를 사용한다.

별도 Unity 플레이에서12회 연속 재활성화/전송, 매번 새 편집 요소/빈 버퍼/포커스, IME 소유권 활성화·종료, 닫힌 뒤 늦은 조합 이벤트 무시, 채팅 입력칸1개 유지, 한글 초안 복원, 기존 확정/전송/게임 입력 동작을 합쳐142개 검사를 통과했다. 실제 OS 한글 자판 조합은 자동화하지 못했으므로 합성 문자/조합 이벤트 검사와 구분한다. 기존 실패 상태가 남은 플레이 세션은 종료 후 다시 실행해야 한다. 프로토콜39/RPC/경기 판정은 변경하지 않는다.

한글 조합/전송 재수정 검증: 별도 Unity 플레이에서 물리 Enter의 기본 확정 처리, CR/LF 차단, 조합 중 Enter→별도 프레임의 조합 종료→Return 코드를 포함한 최종 한글 본문→실제 호스트 RPC/채팅 기록 도착을3회 반복했다. 완전한 본문/중복 없음/전송 후 입력칸 비움/대기 중 Esc 취소와 기존35개를 합쳐54개 검사를 통과했다. 이 실행에서 GeneratePreviewString/ReplaceSelection 예외는 없었다. 사용자 Editor.log의 실제 조합 예외를 근거로 수정했지만 OS 한글 자판 자모 입력 자체는 자동화하지 못했다. 아래47/35/56개는 이전 수정 단계의 검사 기록이다.

첫 글자 재수정 검증: 수정 전 코드에서 Enter 문자 이벤트를 보내 편집 포커스가 풀리는 실패를 재현했다. 수정 후 CR/LF 각각의 첫 영문/한글 보존, 네이티브 IME 모드 유지, Input System의 실제 IMECompositionEvent 구독/Enter 전송 차단/확정 문자 전송, 기존 포커스10개/로컬25개를 합쳐47개 검사를 통과했다. 한글 문자는 UI KeyDownEvent로 주입했고 OS 한글 자판의 실제 자모 조합은 자동화하지 않았다. 이전35개 검사는 별도의 Enter 문자 이벤트를 포함하지 않아 이 문제를 검출하지 못했다.

Enter/포커스 회귀 검증: 별도 Unity 플레이에서 메뉴/준비 버튼의 NavigationSubmit 차단, Enter/숫자패드 Enter로 실제 편집 요소 포커스, 마우스 클릭 없는 한글/숫자 KeyDownEvent 입력, 커서 위치, 전송 한 번, Esc 닫기, 초안 끝에서 이어 쓰기10개 검사를 통과했다. 입력칸 값을 직접 대입하지 않고 현재 포커스에 텍스트 이벤트를 보내 검사했다. 숨김 에디터에서 InputSystem.QueueTextEvent는 UI Toolkit의 네이티브 텍스트 공급 경로로 전달되지 않아 UI 텍스트 이벤트를 사용했다.
수정 후 기존 로컬25개 검사도 다시 통과했다. 이번 변경 검증은 총35개이며 아래 별도 호스트/원격/늦은 참가 검사는 채팅 최초 구현 때의 기록이다.
