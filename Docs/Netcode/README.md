## 2026-10-29 무기 스킨 (프로토콜86)

리볼버·소드오프·윈체스터에 각 7종의 외형을 추가한다. 기존 아이템 스킨과 무기 스킨을 소유자 쓰기 스킨 NetworkVariable의 각각 다른 4비트에 저장해 호스트·원격·늦은 참가자에게 표시한다. 스킨은 로컬 소유/장착 정보이며 외형만 변경하고 게임 판정에는 영향을 주지 않는다. 뽑기는 아이템 50종과 무기 21종을 같은 확률로 선택하고 룰렛은 결과 등급에 맞춘다.

## 2026-10-29 피격 스킨 보존 (프로토콜85)

서버는 테이저 또는 먹물이 실제 명중할 때 공격자의 스킨 색을 피격자 상태에 기록한다. 이후 빗나간 발사나 공격자의 이탈에도 색을 유지하며, 여러 명이 명중시키면 마지막 명중의 색을 사용한다. 스냅샷 직렬화와 동등성에 포함하고 게임 판정은 바꾸지 않는다.

## 2026-10-29 로비 연습 스킨 표시 (프로토콜84 유지)

테이저의 발사광과 먹물 피격 색은 공격자가 장착한 스킨을 각 화면에 표시한다. 로비 준비 연습 중 총기 발사에는 총알 스킨 연출만 미리 보여주며 탄약·아이템 사용이나 추가 사격을 부여하지 않는다. 실제 경기의 총알 연출은 기존 아이템 사용 상태를 따른다. 기존 스냅샷과 스킨 정보만 사용하며 게임 규칙과 네트워크 형식은 바꾸지 않는다.

## 2026-10-29 윈체스터 지향사격 정확도 (프로토콜84)

윈체스터 지향사격은 서버가 조준 중심을 포함하는 반경 10도 범위에서 탄도를 선택한다. 기존 35~70도 중심 제외 방식보다 명중할 가능성이 생기며 정조준 퍼짐 0과 히트스캔·다른 무기의 판정은 유지한다. 로비 연습과 본 경기에 동일하게 적용하고 기존 발사 방향 스냅샷으로 탄흔을 동기화한다.

## 2026-10-29 SR 이상 아이템 스킨 연출 (프로토콜83 유지)

테이저·먹물팩·총알·응급 앰플의 SR 이상 스킨 연출과 효과음은 기존 좌석별 스킨 NetworkVariable 및 발사·사용 스냅샷을 이용한 클라이언트 표시다. 피격자의 먹물·감전 색은 해당 사건의 공격자 상태에서 찾는다. 회복량·피해·사거리·시야 가림 시간과 불투명도·소모는 바꾸지 않는다. 새로운 네트워크 필드나 RPC는 없다.

## 2026-10-29 윈체스터 지향사격 탄퍼짐 (프로토콜83)

윈체스터는 정조준 시 퍼짐 없이 서버가 조준 방향을 즉시 판정한다. 지향사격은 이전 규칙대로 조준 중심에서 35~70도 벗어난 방향을 서버 난수로 선택한다. 로비 연습과 본 경기에 공통 적용하며 실제 발사 방향을 기존 스냅샷으로 전달해 탄흔과 판정을 일치시킨다. 다른 무기의 퍼짐은 바꾸지 않는다.

## 2026-10-29 윈체스터 즉시 사격 (프로토콜82)

윈체스터는 서버에서 발사 즉시 최대 20m 광선으로 플레이어·가림·테이블 소품을 판정하고 기존 피해 및 목숨 규칙을 적용한다. 로비 연습도 즉시 판정한다. 원격 화면의 탄흔은 발사 스냅샷으로 재현하는 표시 효과이며 피해 권한은 없다. 테이저의 5.5m 즉시 판정과 다른 총기의 유한 속도 투사체는 유지한다.

## 2026-10-29 아이템 외형 스킨 (프로토콜81)

스킨 획득과 장착은 기기별 로컬 저장이며 게임 능력에 영향을 주지 않는다. 참가자의 소유자 쓰기 NetworkVariable로 장착 색상만 공개해 호스트, 원격 참가자 및 늦은 참가자가 표시한다. 색 인덱스는 표시할 때 범위를 제한한다. 재화와 계정 연동은 없다.

## 2026-10-29 테이저 발사 후 무기 복귀 (프로토콜80)

실제 대난투와 일반 사격 턴에서 테이저는 명중 여부와 관계없이 발사 0.4초 뒤 서버가 주총기로 복귀시킨다. 로비 연습은 계속 테이저를 들며, 대난투에서는 보관한 총기 장전 상태를 복원한다. 발사 기록·쿨타임은 유지하며 종료를 확정하는 발사도 복귀 딜레이를 기다린다.

## 2026-10-29 방장 로비 연습 (프로토콜79)

방장은 별도의 연습 준비/취소로 로비에서 사격·아이템 연습을 할 수 있다. 방장 준비 비트는 시작 조건에서 제외하며, 참가자가 모두 준비되면 방장이 연습 중에도 시작 버튼을 누를 수 있다. 서버가 방장 소유자·라운드·단계·선택을 검증하고 기존 연습 세션과 준비 스냅샷을 재사용한다.

## 2026-10-29 입장 채팅 공지 (프로토콜78)

서버는 새 참가자에게 기존 채팅을 소유자 전용 RPC로 순서대로 전달한 뒤 공지 표시 완료 신호를 같은 소유자에게 보낸다. 해당 클라이언트는 개인 공지를 마지막 행에 한 번 추가하며 서버 기록이나 다른 참가자의 채팅에는 추가하지 않는다. 방 재입장 시 다시 표시한다.

## 2026-10-29 미니게임 시작 전 장비 전환 (프로토콜77)

로비와 시작 카운트다운, 미니게임 선택·진행·결과 및 아이템 준비 등 비사격 단계에서 보유한 테이저와 먹물팩 및 주총기를 휠로 전환해 들 수 있다. 표시용 장착 상태는 서버가 소유자·좌석·단계·소지·생명·버전을 검증하고 스냅샷으로 공유한다. 장착만으로 아이템을 사용·소모하지 않으며 아이템 사용 단계와 실제 사격의 선택·사용 규칙은 유지한다.

## 2026-10-29 개발자 설정과 생존 체력 (프로토콜76)

아이템 전체 선택·소모품 무한·쿨타임 제거와 사격 제한시간 변경은 방장 본인에게만 적용한다. 다른 참가자와 봇은 일반 선택·소모·쿨타임과 10초 제한을 사용한다. 미니게임 직접 선택은 방장이 선택하고 모두가 함께 진행한다. 서버와 각 소유자 UI가 동일한 좌석별 조건을 사용한다. 모든 미니게임 전환에서 생존자의 체력과 생명 식별자를 유지하며, 사망 후 목숨이 남아 복귀하는 참가자는 체력100으로 복귀한다.

## 2026-10-28 준비 상태 유지 (프로토콜75)

방 설정 변경이나 개발자 모드 해제로 다른 참가자의 준비를 강제 취소하지 않는다. 전체 아이템 선택은 방장에게만 적용하며, 끄면 방장의 기존 수동 선택을 복원한다. 복원된 방장 선택이 부족하면 시작 버튼을 비활성화하고 방장이 아이템을 다시 선택한다.

## 2026-10-28 방장 시작 (프로토콜74)

로비와 최종 재경기에서 방장은 준비하지 않고 참가자 전원이 준비한 뒤 시작 버튼을 누른다. 봇은 자동 준비하며 방장의 아이템 선택도 완료되어야 한다. 서버는 기존 소유자 RPC의 발신자가 실제 방장인지, 좌석·라운드·대기 단계·인원·준비·아이템·접속 예약을 검증하고 시작한다. 참여자 준비 및 취소는 각각 유지하며 자동 시작은 하지 않는다.

## 2026-10-28 최종 결과와 재경기 (프로토콜73)

최종 결과에서는 마우스를 자유롭게 사용하고 무기와 시작 아이템을 다시 선택한다. 서버는 준비한 참가자의 변경을 막고, 준비 취소 시 다시 허용하며 모두 준비하면 새 선택으로 지급한다. 최종 결과는 승리·하이라이트·결과 순서로 소리와 함께 표시하고 이후 장비 선택과 준비 영역을 펼친다. 기존 소유자 RPC와 스냅샷을 재사용한다.

## 2026-10-28 뭐였더라? 오입력 탈락 (프로토콜72)

서버가 입력과 미입력 칸을 모두 계산한 뒤 오입력이 있는 참가자를 모두 미니 탈락시킨다. 정답자가 한 명이면 즉시 1등이고 둘 이상이면 다음 라운드로 진행한다. 남은 전원이 오입력했다면 가장 적게 틀린 참가자가 1등이며, 그 최소 오입력이 동점일 때만 동점자들이 주사위를 굴린다. 해당 라운드 결과에는 그 라운드 참가자만 표시한다. 미니 탈락은 체력·목숨에 영향을 주지 않는다.

## 2026-10-28 멀티플레이 봇 난이도

방장은 싱글플레이 또는 멀티플레이 로비에서 추가할 봇의 난이도를 쉬움/보통/어려움으로 고르고, 마지막에 추가한 봇부터 제거한다. 싱글플레이 로비는 봇 없이 열린다. 각 봇의 행동은 호스트가 개별 난이도로 결정하며 이름에 난이도를 표시해 기존 이름 스냅샷으로 참가자에게 공유한다. 추가와 제거는 호스트만 대기 중 실행하며 별도 네트워크 필드는 없어 프로토콜69를 유지한다.

## 2026-10-28 사격 중 대기 자세

사격·연습 중 캐릭터의 무작위 대기 동작과 호흡 이동을 중지한다. 살아 있고 피격 반응이 없을 때 보이는 머리 중심을 서버의 고정 머리 판정 중심에 맞춘다. 피격·사망·복귀 및 조작 동작은 유지한다. 서버 팔 판정과 자세 추적은 아직 수정되지 않았으며 프로토콜68을 유지한다.

## 2026-10-28 아이템 선택 및 개발 설정 (프로토콜68)

각 참가자는 아이템 사용 시간에 한 종류만 선택하며 같은 아이템을 다시 누르면 취소한다. 시간 종료 시 서버가 유효한 선택 하나를 적용한다. 미선택 아이템은 사격 중 사용할 수 없다. 준비된 선택과 쿨타임 제거 설정을 스냅샷에 직렬화한다. 아이템 무한 사용은 소모품만 보존하며 쿨타임 제거는 별도 옵션이다. 개발용 전체 선택은 수동 선택을 덮어쓰지 않고 해제 시 복원한다. NGO 2.13.3 / Transport 2.7.3 유지.

## 2026-10-28 사격 전 시선 유지 (프로토콜67)

## 2026-10-28 선택 무기와 총알 (프로토콜65)

## 먼저 적용할 규칙

1. 클라이언트-서버에서 중요한 게임 결과는 서버가 결정한다. 소유권과 서버 권한은 다르다.
2. 지속 상태는 `NetworkVariable`/`NetworkList`, 순간 요청·이벤트는 `[Rpc]`로 표현한다.
3. NGO 2.13.3의 RPC 기본 호출 권한은 `Everyone`이다. `SendTo.Server`만으로 소유자 전용이 되지 않는다. `InvokePermission`과 서버의 게임 규칙 검증을 함께 사용한다.
4. `OnNetworkSpawn`에서 이벤트를 구독하고 현재 상태도 즉시 적용한다. `OnNetworkDespawn`에서 구독을 해제한다.
5. `Update`는 스폰 전에도 호출될 수 있다. 네트워크 작업에는 `IsSpawned`와 적절한 권한 검사가 필요하다.
6. `Instantiate`만으로 원격 생성되지 않는다. 등록된 네트워크 프리팹과 권한 있는 `Spawn`/`Despawn`이 필요하다.
7. 하나의 Transform에 여러 동기화 방식이 동시에 위치를 쓰지 않도록 한다.
8. 공유 씬은 NGO 씬 관리와 완료 이벤트를 사용한다. Unity의 `sceneLoaded`만으로 네트워크 준비 완료를 판단하지 않는다.
9. 호스트만 테스트하지 않는다. 원격 클라이언트, 전용 서버, 늦은 참가, 끊김·재접속도 변경 범위에 맞게 확인한다.
10. API가 애매하면 아래 상세 가이드와 설치 패키지를 확인한다. 과거 버전 기억으로 단정하지 않는다.

## 2026-10-27 멀티플레이 직접 접속 복원 (현재 규칙, 프로토콜60)

방 목록 도입 전의 호스트 IP(기본127.0.0.1)·포트(기본7777) 입력과 방 만들기/참가하기로 복원한다. 방 목록·코드·초대 코드·비밀번호 UI와 검색/광고/승인 페이로드 경로를 사용하지 않는다. ## 2026-10-28 로비 선택 아이템 연습 (프로토콜61)

로비의 준비 완료 참가자는 첫 경기 전에 직접 선택한 아이템을 화면 오른쪽 연습 아이템 버튼으로 사용할 수 있다. 연습에서는 선택된 아이템만 서버가 승인하며 반복 사용해도 본 경기의 소모품·쿨타임을 변경하지 않는다. 앰플은 체력이 가득 찬 연습 상태에서도 회복 이펙트를 시험한다. 총알은 표시를 켜고 끌 수 있으며 연습 사격은 기존대로 무제한이다. 패딩은 착용/해제와 테이저 면역을 시험한다. 테이저와 먹물은 아이템 버튼으로 들고 발사/투척하며 선택한 무기 이미지로 돌아가거나 다른 아이템을 선택해 바꿀 수 있다. 테이저 명중은 준비된 상대에게 감전1.3초를, 먹물 명중은 기존 시야 효과를 적용한다. 준비된 사람끼리만 맞고 체력·목숨·킬·실제 보유량에는 영향이 없다. 준비 취소/경기 시작 시 연습 효과와 비행 중 투척을 정리한다. 서버가 소유자·준비·아이템 선택·시각·거리·충돌을 검증하며 스냅샷의 기존 필드를 재사용한다. 게임 시작 시 선택한 실제 아이템을 기존 규칙대로 지급한다. 방 생성자는 NGO 호스트이고 참가자는 IP/포트 직접 연결을 유지한다. 구버전과 의미가 달라 프로토콜61을 사용한다.
