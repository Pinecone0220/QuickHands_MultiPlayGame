# 테이블 총격전 — 최대 6인 생존전

변경일: 2026-10-22. Unity 6000.3.18f1 / NGO 2.13.3 / ProtocolVersion 52. 세부 규칙은 아래 날짜별 최신 기록을 우선한다.

## 파티 모드와 미니게임 선택

- 게임 모드는 **파티 모드 하나**이며 메뉴에 현재 미니게임 목록 `초읽기 / 퀵핸즈 / 신호등 / 욕심의 대가`를 표시한다. 기존 동시 총격전의 이름은 **퀵핸즈**로 바꾸고 파티 미니게임으로 옮겼다. 별도 모드 선택창/독립 퀵핸즈 진입은 없다. AI1~5명·3난이도와 PvP2~6인 모두 같은 파티 흐름을 사용한다.
- 전원 준비 후 **첫 미니게임부터** 서버가 `PartyGames`의 초읽기/퀵핸즈/신호등/욕심의 대가 중 균등 무작위로 하나를 고른다. 퀵핸즈를 고정 첫 게임으로 시작하지 않는다. UI는 공통 서버 시각으로 목록의 이름이 지나가다4.8초 동안 감속해 중앙에 멈추고 선택된 게임을1초 유지한 뒤5.8초에 다음 단계로 진행한다. 이후에는 직전에 실제 진행한 미니게임만 제외하고 고른다. 현재 네 종류이므로 직전에 실제 진행한 게임을 제외한 세 종류 중 균등 추첨한다. 취소된 선택은 진행 이력에 넣지 않으며 최종 재경기에서 이력을 초기화한다. 미니게임 사이에는 준비를 다시 받지 않는다. 미구현 게임 이름은 넣지 않는다.
- 참가자는 **최대 체력100·목숨3개**로 시작한다. 사망/초읽기 미정지마다 목숨1개를 차감하고 현재 미니게임에서는 빠진다. 목숨이 남으면 결과 대기 중 양손으로 테이블을 짚고1.3초에 걸쳐 일어나 다음 미니게임에 복귀한다. 목숨0은 영구 탈락이며 이름표 위에 남은 목숨 수만큼 하트를 표시한다. 자신의 안내는 남은 목숨이 있으면 `목숨을 잃었습니다! / 사인 / 남은 목숨: n`, 목숨0이면 `사망했습니다! / 사인 / 남은 목숨: 0`이며 최종 승리 안내가 덮어쓴다.
- 파티 생존자(`PartyAliveMask`, 연결되어 있고 목숨이 남은 참가자)와 현재 미니게임의 생존자(`AliveMask`)를 분리한다. 파티 생존자가1명/0명 남을 때만 최종 결과/전원 탈락을 확정하며, 최종 재경기에는 사망자를 포함한 연결된 전원이 준비해야 한다.

## 미니게임: 퀵핸즈

- 기존 동시 총격전의 집기/장전 숫자 입력·6연발 리볼버/소드오프·우클릭 정조준/좌클릭 사격·HP100/부위·스플래시 규칙을 사용한다. 시작 전 대기/최종 결과 화면에서 **퀵핸즈용 무기**를 고르며 초읽기에서 공유 리볼버(한 발)를 사용해도 이 선택은 유지된다.
- 현재 참가자끼리 마지막 한 명까지 겨룬다. 첫 사망자만 그 퀵핸즈의 꼴찌다. 같은 첫 사격의 스플래시로 여러 명이 동시에 사망하면 서버가d6를 굴려 낮은 면이 최하위이며 중복은 재굴림한다. 이후 사망자는 기존 꼴찌를 바꾸지 않는다.
- 사망한 사람 **모두 목숨1개씩** 잃는다. 꼴찌만 제외하던 이전 규칙은 폐기했다. 목숨이 남은 참가자는 체력100/새 Life로 다시 참가하고 목숨0은 되살리지 않는다. 한 명만 파티에 남으면 최종 승리로 끝내며, 그 외에는 미니 승리/목숨 차감 요약을5초 보여준 뒤 다음 선택을 진행한다. 동시에 전원이 사망해도 남은 목숨이 있으면 복귀하며, 마지막 목숨까지 전원 잃었을 때만 전원 탈락이다.
- 임시 사망도 쓰러짐·PvP 얼굴 카메라/관전·총기 킬로그·피격 기록을 사용한다. 닉네임 위에는 임시 사망을 `미니게임 탈락`, 파티 제외는 `탈락`으로 표시한다. 부활 시 새 Life를 발급해 체력/사망 연출/피격 내역/마우스 조작을 초기화한다. 해당 생명과 다른 오래된 사망 RPC는 재부활한 자신의 사망 메시지를 띄우지 못한다.
- 킬·실제 피해·숫자 오입력/정확도·초읽기 성적은 파티 전체에서 누적한다. 임시 사망자와 다시 싸워 얻은 킬도 실제 사격 기록이다. 따라서 하이라이트는 반복 처치를 `n명` 대신 `n킬`로 표현한다. 피격 내역은 현재 Life의 기록이며 파티 통계와 분리한다.

## 미니게임: 초읽기
- 초읽기는 테이블 가운데 한 발 장전된 공유 리볼버 **한 자루**를 놓는다. 개인 무기 선택과 집기/장전 숫자 입력은 사용하지 않으며 퀵핸즈용 선택 무기를 덮어쓰지 않는다. 초읽기의 사망/시간 초과도 목숨1개 차감이며 목숨0만 파티 탈락이다.
- 살아 있는 참가자 모두 같은 서버 시각에 시작한다. 목표는 매번 **7~15초 사이의 정수**를 무작위로 선택하고 `7.00초`처럼 표시한다. 1초 준비 후 타이머가 시작된다. 타이머는 시작 후 **2.4~2.9초 사이**의 무작위 시각에 가린다(3초 이전). 목표 시간은 계속 보이지만 경과 시간은 `••.••`가 된다.
- Space로 한 번 정지한다. 마우스 클릭과 화면 안내는 정지 입력으로 사용하지 않는다. 정지 이후 자기 기록도 순위 발표 전까지 숨기며 남의 정지 여부/시각을 실시간으로 공개하지 않는다. 조준 흔들림은 사격 기회를 얻기 전에는 적용하지 않는다.
- 경과 시간을 반올림해 소수점 두 자리로 확정한 후 목표와의 **절대 오차**가 작은 순으로 순위를 정한다. 동일 오차는 서버가 각자 d6 주사위를 굴려 큰 숫자가 앞선다. 중복 숫자가 있으면 해당 동점 그룹 전체를 다시 굴린다. 비정상 RNG에서 무한 반복을 막기 위해 32회 후 남은 면을 중복 없이 뽑는다. 공개 순위에 기록/오차/동점 주사위와 재굴림 횟수를 표시한다.
- **목표+2초까지** 정지할 수 있다. UI는 마감 이후 정지 입력을 막고 더 세지 않는다. 마감까지 정지한 표본의 네트워크 도착에만 최대0.3초 여유를 둔다(추가 정지 시간이 아님). 미정지한 생존자는 서버가 **동시에 목숨1개를 차감**하고 현재 미니게임에서 제외하며 HP0/쓰러짐/관전/사인 `초읽기 시간 초과`를 적용한다. 연결/좌석은 유지하고 가짜 총격 피해·처치자·킬 수·킬로그를 만들지 않는다.
- 정지한 생존자만 순위를 받는다. 미정지자는 순위창 아래 `시간 초과 · 목숨 차감`으로 표시한다. 정지한 생존자가 한 명 이하라면 사격 기회를 생략하고 복귀/다음 선택으로 넘어간다. 목숨이 남은 파티 참가자가 한 명이면 일어난 뒤 최종 승리, 전원 목숨0이면 전원 탈락 결과가 된다. 최종 재경기에는 연결된 전원이 준비해야 한다.
- 순위를 6초간 보여주고 본인 행을 금색 배경·굵은 글씨·`나` 표시로 강조한 뒤 **아이템 준비5초** 뒤 1등에게만 생존 상대를 자유롭게 조준하는 사격 기회를 준다(기본10초, 방 설정 적용). 총을 꼴찌 몸통 쪽으로 처음 돌려 주되, 이후 직접 마우스로 조준하고 우클릭 홀드 정조준/좌클릭 사격한다. 다른 생존 상대 누구에게나 실제 투사체가 맞으면 피해가 들어간다. 시간 안에 발사하지 않으면 기회가 끝난다.
- 기존 흔들림/퍼짐/가림/부위 판정과 HP100, 리볼버 머리100·몸통50·다리35를 사용한다. 실탄/공포탄 확률은 없다. 빗나가거나 비치명타면 상대가 살아남으며 사격 한 발 또는 제한 시간 종료 후3초 뒤 **초읽기/퀵핸즈 목록에서 다음 게임 선택**으로 이어진다. 초읽기 종료 시 살아 있는 참가자의 남은 체력은 유지하고, 죽었지만 목숨이 남은 사람은 체력100/새 Life로 복귀한다. 퀵핸즈 종료 시에는 모든 잔여 목숨 참가자를 체력100으로 회복한다.
- 최종 결과표는 플레이어·오입력·킬·입력 정확도·초읽기1등 횟수·평균 오차를 함께 표시한다. 두 미니게임의 기록이 섞여도 보존하며 초읽기 평균은 정상 정지 기록만 포함한다. 실제 경기 기록에 따른 하이라이트도 지원한다.
- `StopClockRpc`는 소유자→서버 reliable 요청이다. 서버는 발신자/소유 좌석/경기 번호/초읽기 번호/생존/중복 정지/유한 시각/시작~마감 범위를 검증한다. 클라이언트의 NGO ServerTime 표본은 서버 수신 시각 기준 과거0.3초~미래0.05초만 허용한다. 승인 여부는 서버→소유자 reliable RPC로 알린다. 큰 지연의 정지는 거절될 수 있으며 완전한 부정행위 방지 방식은 아니다.
- 선택된 미니게임·선택/시작/숨김 시각·목표·순위/주사위·자동 탈락·파티 생존 마스크·개인 Life/사인/선택 무기를 `DuelSnapshot`으로 동기화한다. 정지 원본은 Counting 동안 공개하지 않는다. 서버는 해당 미니게임/단계에 맞는 요청만 허용하며 초읽기에서도 사격자 외의 모든 현재 생존 상대가 피해 대상이다. 미니게임 전환/부활마다 행동 Version도 바꿔 오래된 입력/사격을 거부한다. 부활한 현재 Life와 다른 피격 보고는 표시하지 않는다. 프로토콜30은 이전 빌드와 호환되지 않는다. LivesRemaining과 ReviveAt을 서버 스냅샷으로 동기화하고 목숨 차감 안내 RPC에도 확정 잔여 수를 담는다.
- 현재 규칙 검사는 `Tools/Test-ClockContest.ps1`(초읽기/파티 통합)과 `Tools/Test-SixPlayers.ps1`(총격/파티 반복)이다. Unity 실제 타입 직렬화/하이라이트는 `Tools/UnityQA/ClockBuildChecks.cs`, 목숨3개/원격 소유자 안내/양손 테이블 지지/순환/영구 탈락/최종 결과/재경기 검증은 `Tools/UnityQA/LivesRuntimeQA.cs`를 사용한다. 이전 규칙의 혼합 파티/전용 초읽기 검사는 `MixedPartyRuntimeQA.cs`, `PartyRuntimeQA.cs`, `ClockRuntimeQA.cs`에 역사 자료로 보관한다.
- 초기 버전(프로토콜20) 검증: 초읽기 규칙1,100개 및 기존 총격전552개 검사, Unity Windows 빌드, 실제 스냅샷/통계 직렬화와 동등성, 기존 하이라이트40개 검사 통과. 별도 그래픽 호스트+원격5명에서 타이머 숨김/기록 비공개/6인 동점 주사위 일치/공유 총1자루/실제 마우스 클릭 사격/빗나감·몸통50 피해 이후 반복/5명 탈락·원격 소유자 사망 내역/결과 통계/탈락자 포함 전원 준비 재경기를 확인했다. AI5명 실제 경기·자동 준비·재경기도 완료했다. 1200×800 타이머/순위/사망 내역과 중앙 결과표를 렌더 확인했다. 인터넷 고지연/패킷 손실과 전용 서버 실기동은 미검증이다.
- 파티 모드(프로토콜21) 검증: 규칙1,157개/기존 총격전552개, 선택/자동 탈락/사인 스냅샷 직렬화와 동등성/전원 탈락 결과 및 하이라이트40개 검사, Unity Windows 빌드 통과. 실제 그래픽 호스트+원격5명에서 미니게임 선택/목표+2초 마감/4명의 동시 자동 탈락/정지 생존자끼리 사격/단독 생존 승리/전원 미정지 시 전원 탈락/모든 탈락자의 준비 재경기를 확인했다. AI5명 경기에서 사람의 시간 초과 사망/AI 자동 준비/재경기도 통과했다. 1200×800 선택 릴/시간 초과 사망/전원 탈락 결과를 렌더 확인했다.
- 혼합 파티(프로토콜22) 검증: 초읽기1,157개·총격/파티 반복923개·통합191개 규칙, 실제 Unity 직렬화/피격 Life/하이라이트40개 검사 및 Windows 빌드 통과.32개 초기 시드로 첫 선택에서 두 게임 모두 나옴을 확인했다. 실제 호스트+원격5명에서 퀵핸즈→초읽기→퀵핸즈→초읽기, 미니 승리 후 꼴찌 한 명만 제외/나머지 Life·체력·시점 복귀, 원격 피격 내역 초기화와 새 생명의 기록, 실제9킬/900피해/입력·초읽기 누적 결과/전원 준비 재경기를 확인했다. AI5명 혼합 경기에서도 초읽기 총격 사망자의 영구 제외와 파티 최종 한 명/자동 준비/재경기를 통과했다. 새 AI 방의 **첫 선택 화면**에서 두 이름이 같은 릴에 표시되고 초읽기가 선택되어 시작하는 것도 렌더 확인했다.

- `Assets/Scenes/SampleScene.unity`에서 Play. AI 난이도를 선택하거나 PvP 방을 만들고 IP/포트로 참가한다.
- AI는 사람 1명+AI 1~5명(총 2~6명). 메뉴의 상대 AI 수를 선택한다. PvP는 2~6명이다. 원하는 참가자가 들어온 뒤 **모두 준비 완료**를 눌러 시작한다.
- PvP 방 만들기는 지정 UDP 포트가 점유/예약되어 있으면 근처 빈 포트(최대 32개 후보) 또는 OS가 선택한 빈 포트로 만든다. 메뉴의 포트 입력값과 대기창의 `접속 포트`에 실제 번호를 표시한다. 다른 참가자는 이 번호로 접속해야 한다. 참가하기는 입력한 포트 그대로 접속한다. AI전은 자동 임시 포트를 사용한다.
- 첫 경기와 재경기 모두 연결된 전원이 준비해야 한다. 탈락자도 준비 대상이다. AI는 자동 준비하지만 사람의 준비를 대신하지 않는다.
- 방에 들어온 뒤 하단에서 데린저 또는 단발 소드오프를 선택하고 준비한다. 기본값은 데린저다. 준비 후와 경기 중에는 변경할 수 없다. 재경기에서도 선택을 유지하며, 준비 전에 바꿀 수 있다. AI전 사람도 동일하게 선택하며 AI는 기본 데린저를 사용한다.
- 키보드 1~5 키 또는 숫자 패드로 왼쪽부터 입력한다. 누른 채 유지해도 반복 입력되지 않는다. 화면의 예시 숫자 버튼은 제거했다.
- 숫자 입력은 무기 집기/장전에만 사용한다. 장전 후 입력창이 사라지며 마우스로 직접 겨냥한다. 오른쪽 버튼을 누르고 있으면 무기별 아이언사이트 정조준, 왼쪽 버튼을 누르면 한 발을 쏜다. 정조준 없이도 발사할 수 있으나 흔들림과 퍼짐이 크다. Escape로 커서를 풀고 장면을 클릭해 다시 잡는다(복귀 클릭은 발사하지 않음).
- 생존 상대의 정조준 판정이 본인을 향하면(데린저 중심선, 소드오프 제한된 방사 범위) 붉은 가장자리 경고가 표시된다. 본인이 정조준 중이면 붉은 경고는 95% 감소하며 같은 형태의 검은 가장자리가 표시된다. 소드오프는 1.2배, 데린저는 1.4배로 시야를 확대한다. 놓거나 사망/종료/연결 끊김 시 해제된다.

## 닉네임

메뉴에서 닉네임을 입력한 뒤 AI전/방 만들기/참가하기를 누른다. 비워 두거나 공백만 입력하면 방에 입장한 순서대로 `player1`, `player2`…를 서버가 지정한다. 닉네임을 직접 입력한 사람도 입장 순서에 포함하며, 중도 이탈자의 자리를 재사용해도 번호는 재사용하지 않는다. 예: 두 번째 참가자 이탈 후 다섯 번째 참가자가 들어오면 빈 좌석에 `player5`가 표시된다. 새 방을 시작할 때 순번을 초기화한다. AI 1명은 `AI`, 여러 명은 `AI1`~`AI5`로 표시한다.

한글 포함 최대 16개 문자 요소/UTF-8 60바이트로 정리한다. 앞뒤 공백, 제어 문자, 방향 제어 문자, 꺾쇠를 제거한다. 텍스트는 리치 텍스트로 해석하지 않는다. 머리 위 표시가 머리 위치를 따라가며 카메라 뒤/화면 밖/자신의 얼굴 추적 중에는 숨긴다. 준비 명단·탈락·승리 메시지도 같은 닉네임을 사용한다.

준비 대기·준비 완료·생존·탈락 상태는 보이는 캐릭터의 닉네임 위에 표시한다. 빈 좌석은 의자에 `빈 자리`로 표시하며 상단 명단에서 숨긴다. 상단 창과 수동 겨냥 버튼은 제거했다. 자신의 준비 여부는 하단 준비 버튼에서도 확인할 수 있다. 나가기 버튼은 `자리에서 일어나기`이며 높이 52px, 최소 너비 190px로 표시한다.

ConnectionData로 받은 닉네임을 서버가 다시 검증하고 입장 시 확정한다. 6개 FixedString64Bytes 이름을 경기 스냅샷에 포함해 기존 참가자와 늦게 입장한 참가자가 같은 이름을 받는다. 닉네임은 계정 인증 정보가 아니며 중복 입력도 허용한다.

## 입력창과 승패

| 무기 | 동작 순서 | 동작별 입력 | 피해 |
|---|---|---|---|
| 단발 데린저 | 집기 → 잠금 해제 → 열기 → 장전 → 닫기 → 격철 → 마우스 조준/사격 | 6자리 × 6행동 = 36개 | 머리 100 / 몸통 50 / 다리 35 |
| 원배럴 소드오프 | 집기 → 열기 → 장전 → 닫기 → 마우스 조준/사격 | 4자리 × 4행동 = 16개 | 부위 구분 없는 방사 직격75 / 양옆25 |

경기 입력창에는 장전 행동 이름과 무기별 숫자만 표시한다. 장전 완료 후 숫자 조준/사격 단계는 없다. 최대 체력은 100이며 피해는 퍼센트가 아닌 고정 정수다. 머리/몸통/다리별 피해를 누적하고 0이면 사망한다. 기존 흔들림(정조준0.55도/일반1.8도·진입0.6초 안정화)에 데린저3.5배, 소드오프1.75배를 적용한다(2026-10-13: 소드오프는 변경 전 데린저 수준, 데린저는 변경 전의2배). 데린저 한 발의 서버 퍼짐은 정조준/일반0.65/4.5도다. 소드오프는 정조준/일반3/6도 원뿔 안의37개 탄환을 매 발사 무작위로 분산한다. 빠른 장전 이후에도 수동 정확도와 가림/퍼짐 때문에 역전할 수 있다. 과거 제조사 조사는 [단발 데린저 근거](Weapons/Derringer-Balance.ko.md)에 보존한다.

오입력은 현재 행동의 입력 진행을 초기화하고 0.45초 정지한다. 데린저는 서버가 6개 숫자를 다시 뽑고 각 자리가 이전 숫자와 다르게 바뀐다. 행동 종류는 유지한다. 클라이언트는 새 패턴을 수신할 때까지 숫자를 숨기고 입력을 기다린다. 소드오프는 기존 숫자 패턴을 유지한다. AI와 PvP 모두 동일한 서버 규칙을 사용한다.

오입력 시 본인의 행동 입력창 전체가 약 0.32초 동안 좌우로 작게 흔들린다(최대 7px, 점차 감쇠). 데린저/소드오프 모두 적용하며 정답이나 다른 참가자의 오입력에는 발생하지 않는다. 사망·경기 종료·새 경기·자리에서 일어나기 시 위치를 원래대로 되돌린다. 로컬 표시 효과이며 기존 벌칙과 서버 입력 규칙은 그대로 유지한다.

2026-10-12 데린저 입력 표시는 완료한 숫자와 지금 입력할 숫자만 공개하고 이후 칸은 숫자를 숨긴 빈칸으로 유지한다. X 등 대체 문자는 사용하지 않는다. 완료 숫자는 기존 초록색 표시를 유지한다. 오입력으로 진행이 초기화되면 첫 숫자만 다시 공개하며 다음 행동도 같은 방식으로 시작한다. 데린저는 장전 6행동·각 6자리이며, 소드오프는 기존처럼 4자리를 모두 표시한다.

- 최대 체력 100에 고정 부위 피해를 누적해 0이면 탈락한다. 데린저 머리 한 발은 100, 몸통 두 발은 50+50, 다리는 35씩이다. 소드오프는 부위 구분 없이 직격75와 이웃25 피해다. 자기 자신이나 사망자는 주 목표가 될 수 없다.
- 소드오프 스플래시는 좌석 번호 기준 바로 이전/다음에 적용한다. 원형 배치지만 1번과 6번은 연결하지 않는다. 화면 기준 1번 목표는 2번에만, 6번 목표는 5번에만 번지고, 2~5번 목표는 양쪽 번호에 번진다. 내부 좌석은 0~5이므로 좌석 0의 이웃은 1뿐이고 좌석 5의 이웃은 4뿐이다. 빈 자리·탈락자·사격자 본인은 피해 대상에서 제외하며 건너뛰지 않는다. 한 발의 모든 피해를 적용한 뒤 사망·승리를 함께 확정한다.
- 죽지 않은 피격자는 짧은 피격 연출만 재생하며 자신의 행동·입력·Version·벌칙은 유지한다.
- 탈락자는 테이블 위로 앞으로 쓰러지고 입력이 차단되며 관전한다. PvP 사망은 얼굴 시점으로 쓰러진 뒤 관전한다.
- 생존자가 둘 이상이면 사격·피격 연출 중에도 각자 입력을 계속한다. 사격자는 즉시 다음 총 집기 입력을 시작하며, 다른 생존자의 행동·숫자·진행·입력 Version·오입력 벌칙·AI 입력 일정은 유지한다. 마지막 생존자가 정해진 뒤에만 1.65초간 종료 연출 후 준비 화면으로 전환한다.
- 다른 참가자의 탈락 알림은 킬로그로만 표시한다. 자신의 사망은 중앙 알림으로 표시한다. 피격 연출 중에도 생존자의 행동 이름·숫자·입력 진행을 그대로 표시하며 탈락/관전 문구로 대체하지 않는다. 탈락자의 하단 입력창은 숨기고 경기 종료 뒤 준비 UI를 다시 표시한다.
- 사격한 사람만 총 집기부터 다시 시작한다. 다른 생존자의 입력 진행은 유지한다.
- 최후의 1명만 승리한다. 종료 후 준비 상태는 초기화되며 자동 재시작하지 않는다.
- 서버가 받은 순서대로 판정한다. 네트워크 지연 보상/동률 판정은 아직 없다.

장전 숫자 입력 중에는 카메라의 조준 흔들림이 없고 마우스 사격 단계에서만 적용한다. 크로스헤어는 표시하지 않는다. 사망 시 왼쪽 카드에 해당 경기의 피격을 시간순으로 표시한다: 공격자(피격 당시 이름), 무기, 데린저 머리/몸통/다리 직격·소드오프 부위 동일 방사 직격 또는 주변 스플래시, 실제 감소한 체력, 최종 타격. 결과표는 승리 문구와 동일한 화면 가로 중앙에 놓고 좌우 여백을 대칭으로 적용한다. 사망 카드의 폭은 왼쪽 공간에 맞추며 두 패널은 겹치지 않는다. 다음 경기/방 나가기까지 기록을 유지한다. 현재 체력 100·최소 피해 25·회복 없음에 따라 한 생명의 피해 기록은 최대 4건이다. 중앙 사망 알림과 승리 우선 연출은 동일하다.

## 6인 원형 공간

모든 좌석은 오른손잡이 기준이다. 총은 자신의 오른쪽에 손잡이가 오른손 쪽을 향하도록 놓이며 오른손으로 집기·조준·사격하고 왼손으로 배럴 개폐와 장전을 보조한다. 데린저는 짧은 단일 배럴과 작은 손잡이이며 회전 실린더가 없다. 별도 잠금 해제·열기·한 발 삽입·닫기·격철 입력 단계에 따라 레버·배럴·탄·격철이 움직인다. 소드오프는 짧은 원배럴·잘린 나무 개머리판·앞손잡이이며 힌지로 배럴을 아래로 꺾어 열고 빨간 셸 한 발을 삽입한 뒤 별도 닫기 입력으로 닫는다. 캐릭터는 로컬 -Z를 바라보므로 신체의 오른쪽은 로컬 -X다. 좌석 회전을 적용해 P1~P6와 AI 모두 같은 자세를 사용한다.

기존 어두운 방의 분위기를 유지하며 지름 7.5의 원형 테이블로 변경했다. 좌석은 반지름 4.2에서 60도 간격으로 배치하고 이웃 간격은 4.2, 맞은편 간격은 8.4다. 방의 네 벽은 중심에서 ±10에 배치했다. 대기용 카메라(높이 3.5, 수평 거리 7.6)와 관전 카메라(높이 6, 수평 반지름 약 8.5)가 모두 방 내부에 위치한다. 경기 중에는 자기 좌석의 눈 위치(높이 1.91, 중심에서 앞 0.17)에서 자유롭게 마우스로 둘러본다. 캐릭터는 골반·허벅지·무릎·정강이·신발과 목/어깨/몸통을 갖추고 의자는 좌판·등받이·4개 다리·보강대를 갖춘다. 상체만 테이블로 접히며 하체는 의자에 남는다. PvP에서 패배하면 카메라가 얼굴 위치와 회전을 따라 약 0.95초 동안 쓰러지고, 쓰러진 얼굴 시점에서 1초 유지한 뒤 0.4초에 걸쳐 관전 시점으로 전환한다. 얼굴 안쪽이 보이지 않도록 근접 구간에서 자신의 머리 렌더러만 숨긴다. AI전은 기존의 즉시 관전 전환 연출을 유지한다. 신체는 사망 시각을 기준으로 약0.95초에 걸쳐 테이블로 숙여진다. 목숨이 남으면 결과 대기 끝1.3초 전부터 양손을 고정된 테이블 접점에 짚고 상체를 일으킨다. 소유자 카메라도 회복 중 얼굴 위치로 복귀하며 목숨0은 쓰러진 상태와 관전을 유지한다.

AI 1~5명을 선택할 수 있고 선택한 난이도가 모두에게 적용된다. 각 AI는 독립적인 입력 간격·진행·실수·벌칙을 사용하며 기본 데린저의 장전 6행동·각 6자리 후 실제 방향으로 조준하고 발사한다. 쉬움/보통/어려움은 추가 조준 시간 0.85/0.55/0.30초, 조준 오차 최대 3/1.25/0.35도, 머리 선택 확률 12/30/55%로 차이를 둔다. 대상 선택은 AI 의사 결정에만 사용하며 서버의 동일한 부위/가림/퍼짐 판정을 거친다. AI가 여러 명이면 AI1~AI5로 표시한다. 사망한 AI는 입력을 멈추며 승패와 무관하게 종료 연출 뒤 모두 자동 준비한다. 사람이 준비해야 재경기가 시작된다.

## 네트워크와 수명주기

처치가 확정되면 오른쪽 위에 `공격자 [해당 총기 아이콘] 피해자` 킬로그를 표시하며 화살표는 사용하지 않는다. 데린저와 소드오프의 서로 다른 실루엣 이미지를 사용한다. 최근 최대 3개를 표시하고 각 로그는 6초 유지(마지막 1초 페이드)한다. 경기/세션 변경 시 초기화한다. 서버에서 확정한 닉네임·무기·피해 좌석을 Reliable 소유자 대상 RPC로 전송하며 경기 번호·사격 번호·피해 좌석으로 중복을 제거한다. 한 발의 스플래시로 여러 명이 사망하면 각 피해자의 로그를 표시한다. 비치명적 피해는 킬로그를 만들지 않는다. 늦은 참가자에게 과거 처치를 재생하지 않는다. AI 처치도 같은 서버 경로를 사용한다.

최후 생존자 확정 시 화면 중앙에 `닉네임 승리`를 0.8초 표시한 뒤 0.6초 동안 상단으로 올린다. 그다음 한 줄 하이라이트를 중앙에 0.8초 표시하고 0.6초 동안 승리 문구 아래로 올린다. 두 이동이 끝나면 경기 결과표를 표시한다. 세 패널은 다음 경기 시작 또는 방 나가기까지 유지한다. 결과표에는 참가자별 오입력 횟수·실제 킬 수·입력 정확도와 경기 시간이 나오며 최장 연속 항목은 제거했다. 입력 정확도는 서버가 인정한 정답 수 / (정답 수 + 오입력 수)이며 입력하지 않았다면 `—`다. 스플래시의 여러 사망자는 각각 킬에 포함하고 이탈은 킬로 세지 않는다.

하이라이트는 서버가 종료 기록의 후보를 비교해 더 드문 사건 하나를 고정한다. 무킬 피해는 실제 피해 합계가 최대 체력(현재 100) 이상일 때만, 빗나감 박제는 탈락자가 3발 이상 쏘고 피해 0일 때만 후보가 된다. 한 발 3명 처치, 체력 10 이하 우승, 1킬당 실제 피해 35 이하로 여러 킬을 챙긴 마무리 등은 높은 우선순위를 받는다. 오입력은 탈락자의 10회 이상·정확도 75% 이하일 때, 완벽 입력/체력 100 우승은 4인 이상에서 3킬 이상일 때만 고른다. 입력 0회 탈락은 3인 이상·10초 이하 경기, 빠른 종료는 4인 이상·12초 이하·실제 처치로 전원 탈락한 경기로 제한한다. 총격이 실제로 있었던 무사격 우승과 120초 이상·10발 이상 장기전도 후보다. 재미있는 사건이 없으면 게임이 n초 만에 종료되었습니다 형식의 한 문장으로 표시한다. 50 피해 같은 평범한 비치명적 피해나 일반적인 무실수 입력을 억지로 박제하지 않는다. 피해는 상대 체력에서 실제 감소한 값으로 과잉 피해를 제외하고, 실제 없는 무기·사건은 꾸며내지 않는다. 문구는 실제 기록을 담은 짧은 한 문장으로 통일하고 통계 나열·덧붙인 농담을 쓰지 않는다. 한 발 다중 처치는 목숨3개 규칙에 맞게 n킬로 표시하며 즉시 영구 관전으로 갔다고 단정하지 않는다. 서버가 한 번 고정하므로 참가자 모두 같은 문구를 받는다.

결과표 아래에 준비 인원, 항상 펼쳐진 무기 선택, 준비 버튼을 배치한다. 접기/펼치기 조작은 없다. 종료 연출이 끝나면 준비/무기 선택이 활성화된다. 첫 경기의 기존 준비 UI는 유지한다. 서버가 경기 시작 참가 명단과 종료 시 이름/통계를 고정해 이탈·자리 재사용·무기 변경에도 지난 결과가 바뀌지 않는다. 종료된 방의 늦은 참가자는 승리 이동을 재생하지 않고 상단 승리 문구와 결과표를 바로 받는다. 새 경기 시작 시 패널과 통계를 초기화한다.

자신이 처치되면 같은 중앙 알림에 `사망했습니다!`와 `사인 (처치자 닉네임)`을 두 줄로 4초간 표시한다. 승리 확정 알림이 사망 알림보다 우선하며 즉시 덮어쓴다. 이미 승리를 표시한 경기에서는 늦게 수신한 처치 RPC로 사망 알림을 다시 표시하지 않는다. 닉네임이 중복되어도 정확히 판별하도록 서버가 피해 좌석도 전송한다.

- `RouletteRules`: Connected/Alive/Ready 비트마스크, 좌석별 체력·직격/스플래시 누적 피해, 목표 검증, 최후 생존자.
- `WeaponRules`: 무기 종류·입력 길이·행동 순서·물리적 이웃 좌석 정의.
- `DuelGunplay` / `DuelFirstPerson`: 서버 부위/가림/흔들림/퍼짐 수학과 소유자의 마우스/커서/아이언사이트 카메라 입력.
- `DuelDirector`: 좌석별 숫자 Version, 장전/발사 검증, 실제 조준 방향/부위, 피해/사망과 AI/재시작.
- `DuelSnapshot`: 여섯 좌석과 경기 상태를 원자적인 NetworkVariable로 직렬화한다. 무기·체력·피격 시각·현재 행동의 숫자와 진행도를 포함한다.
- `HelloWorldPlayer`: 소유자 전용 숫자/준비/무기 선택 RPC와 실제 발신자 검사. 준비/선택 요청은 경기 번호도 검사한다.
- `HelloWorldManager`: 승인 예약까지 포함한 최대 6명 제한, 빈 좌석 할당, 참가/이탈/서버 판정.
- `RouletteView`: 준비 전 무기 선택, 살아 있는 플레이어만 4/6자리 단일 입력창, 전원 준비 표시, 실제 정조준 시 경고, 무기별 킬로그.
- `RouletteTable`: 여섯 좌석의 총/인물, 동작 진행, 사망 시각으로 파생한 쓰러짐과 관전 시점.

입력마다 숫자 범위·소유 좌석·생존·연출 단계·Version·벌칙을 검사한다. 다른 사람의 입력이 내 Version을 바꾸지 않는다. 숫자 강조만 로컬 예상 표시하고 단계/피해는 서버가 확정한다. 각 동작의 시작과 사망 시각을 동기화해 초기 상태 수신에서도 현재 자세를 복원한다.

진행 중 참가를 거절한다. 대기/경기 종료 후에는 빈 좌석에 참가할 수 있다. 인원 변동 시 기존 준비는 취소하여 새 명단으로 모두 준비하게 한다. 경기 중 이탈자는 생존 집계에서 제외한다. 마지막 한 사람이 남으면 승리하며 1명으로는 다음 경기를 시작할 수 없다. 호스트가 떠나면 세션을 종료한다. 자동 재접속/호스트 이전은 없다.

패키지는 업그레이드하지 않았다. 실제 피해/사격 기록과 고정 하이라이트의 직렬화 확장으로 프로토콜이 19로 바뀌었으므로 모두 같은 새 빌드를 사용해야 한다. 공식 API 근거는 `Netcode/README.md` 및 상세 가이드 6~8·10·12~13절을 따른다.

## 2026-10-12 투사체와 사격시간 방 설정

- 두 무기는 총구에서40m/s로 이동하는 탄환을 사용한다(최대20m). 서버가 매 틱 이동 구간을 검사해 머리/몸/다리·테이블/의자/벽에 닿으면 탄환을 멈춘다. 클라이언트는 맞았다는 좌석이나 피해량을 보내지 않고, 기존 소유자 FireRpc의 각도/ADS/Version/시각 요청만 보낸다. 발사 즉시 장전을 다시 시작할 수 있고, 피해는 탄환이 도착한 뒤 적용한다. 같은 틱에 도착한 탄환은 맞교환이 가능하다.

## 2026-10-13 방장 직접 선택·첫 아이템 (프로토콜32)

선택 무기에 BAS(값3)를 추가한다. 기존 리볼버0/소드오프1/테이저2는 유지하며 선택 목록은 명시적인 Revolver/SawedOff/BAS 배열이다. 로비·최종 결과·로컬 무기 HUD·메인 무기 정보·킬로그에 이름과 저격총 아이콘을 제공한다. 준비 연습에서도 선택 가능하며 무한 탄약/비피해 규칙은 그대로다. 다른 미니게임의 공유 한 발 리볼버 규칙은 유지한다.

BAS는 스코프/올리브색 개머리판/긴 얇은 총열/오른쪽 볼트·탄 배출구를 갖춘 로우폴리 단발 볼트액션이다. 퀵핸즈 처음은 집기→볼트 열기→한 발 장전→볼트 닫기(각4자리, 총16자리), 이후는 볼트 열기(자동 탄피 배출)→한 발 장전→볼트 닫기(총12자리)다. 탄을 배출구에 직접 넣는 모션과 오른쪽으로 나오는 탄피를 표시한다. 몸통/다리는0피해이며 피격 플래시·히트마커·명중음도 없다. 실제 서버 투사체 헤드샷은100피해/현재 미니게임 사망 한 번/목숨2개 차감(0하한)이다. 킬은1회만 기록하고 실제 남은 HP만 피해 통계에 더한다. 잔여 목숨이 있으면 기존 복귀 규칙을 따른다.

BAS ADS는3배율 원형 조준경/검은 외곽/스코프 내부 레티클이다. 자기 총기는 ADS 중 숨겨 시야를 막지 않고 타인 모델은 보인다. 평소/다른 총기의 크로스헤어는 없다. BAS 흔들림은 기본1.8도×5=9도(리볼버6.3도보다 큼), 수직0.7배로 ADS/지향사격이 같다. 지향사격 BAS는35~70도 범위의 중심을 제외한 극심한 무작위 편차, 리볼버는10도 원형 편차다.

모든 총기는 ADS 시 무작위 탄퍼짐0이다. 흔들리는 실제 카메라 조준 방향을 정확히 따라가며 대상 추적/명중 보장/가림 무시는 없다. 서버 ADS 탄환은 눈 앞0.08m의 시선 레이에서 시작해 평행 총구 오차를 없앤다. 렌더 총구는 별도로 기존 정상 무기 위치를 유지하고 트레이서는 그 총구에서 서버 레이 종점으로 이어진다. 소드오프 ADS37발은 같은 조준 방향이며, 지향사격은12도 무작위 산탄/최대6m로 더 가까운 상대만 실제 접촉할 수 있다(ADS20m). 실제 접촉자 중 중앙에 가까운 한 명75와 번호 이웃25를 한 번만 적용한다. 서버와 클라이언트 탄환의 범위가 같다.

발신자/소유권/좌석각도/Version/시간/잔탄 검증과 서버 피해 권한은 유지한다. 새 네트워크 필드/RPC는 없으나 무기 ID와 행동·탄도 의미 변경으로 프로토콜46을 사용한다. 설치 버전 NGO2.13.3/Unity6000.3.18f1/Transport2.7.3은 유지한다. BAS 발사762x54r Single MP3, 볼트Semi 22LR Rack MP3, 장전Pump Shell Load MP3를 사용하고 소드오프 장전도 같은 Pump Shell Load로 교체한다. 원본과 재생성 경로는 Docs/Audio/Sources.md를 참조한다.

BAS 보충: 긴 총을 위한 1인칭 준비 자세는 시야 아래에 옆으로 들어 볼트/배출구와 한 발 삽입을 보여준다. 비조준 탄퍼짐은 발사 방향에만 적용하며 총구의 시작점을 무작위로 옮기거나 렌더 총을 그 각도로 꺾지 않는다. 준비 연습 BAS의 연속 격발 간격은0.8초이며 탄약/HP/목숨은 소모하지 않는다.

## 2026-10-22 BAS 레버액션 외형·탄피 배출 (현재 규칙)
BAS는 사용자 참조 이미지에 맞춘 레버액션으로 정정한다. 오른쪽 볼트 손잡이 대신 아래쪽 큰 레버 고리, 은색 리시버, 어두운 목재 개머리판/앞손잡이, 총열 아래 튜브를 갖춘 로우폴리 형태다. 기존 스코프/피해/탄퍼짐/목숨2개/단발 규칙은 유지한다. 행동 이름은 집기→레버 열기→한 발 장전→레버 닫기(각4자리), 재사격은 레버 열기부터3행동이다. 오른손은 레버 고리를 움직이고 왼손은 앞손잡이를 받치며, 한 발 삽입 때만 왼손이 배출구로 간다. 지정했던 Semi 22LR Rack 녹음(BasBolt 리소스 키)을 레버 열기/닫기에 그대로 사용한다.

실제 사격 후 레버 열기 완료로 서버 SpentMask가 비워지면, 각 화면에서 별도 빈 탄피가 오른쪽 배출구에서 튀어나와 회전/포물선으로0.85초간 이동한다. 탄두 없는 빈 탄피이며 충돌/피해 권한은 없다. 입력 진행률에 탄피가 매달리거나 새 실탄과 같이 움직이지 않는다. 좌석당1개를 재사용하고 첫 빈 총 준비/동일 스냅샷/늦은 초기 상태에는 과거 배출을 재생하지 않는다. 경기/생명/연습 세션 변경 및 무기 해제 시 정리한다. 서버 행동/잔탄/RPC/직렬화는 바꾸지 않는 표시 수정이므로 프로토콜46을 유지한다. 이전 볼트액션 명칭/외형/모션 설명은 이 항목으로 대체한다.

## 2026-10-22 BAS 매 발사 후 필수 레버 입력 (프로토콜47)
BAS는 발사한 순간 소유자 ADS/스코프를 즉시 해제한다. 탄이 있어도 Action이 Aim으로 복귀하기 전에는 서버가 ADS/Fire를 거절한다. 본 경기의 레버 조작→한 발 장전→레버 닫기(각4자리)는 유지한다. 준비 연습에서도 BAS는 발사마다4자리 레버 조작을 완료해야 다시 조준/발사한다. 연습용 탄은 무제한이지만 이 기계 조작은 생략하지 않는다. 다른 총기의 준비 연습은 기존 규칙을 유지한다.

준비 연습에서만 ForSeat의 BAS OpenBarrel/SpentMask를 보존한다. Owner Input 요청은 서버의 현재 연습 참가/무기/단계/Version/자리/마감·오입력 대기를 검사한다. 레버 완료 후 Aim/새 Version으로 전환하며 연습 입력은 실제 Mistakes/CorrectInputs/경기 결과를 바꾸지 않는다. 준비 취소/재준비·새 경기에는 이전 레버 상태를 초기화한다. 연습 입력창에는 레버 조작 이름과4개 숫자만 표시하고 준비 취소 버튼은 유지한다. 기존 배출구 탄피/조작음도 연습 입력 완료에 적용한다. 클라이언트는 발사 요청 직후 pending 상태에서 ADS 재진입을 막고, 서버 상태를 받은 뒤에도 실제 액션 완료를 기다린다.

네트워크 필드/RPC 서명은 같지만 이전 클라이언트는 연습 레버 입력을 지원하지 않으므로 프로토콜47로 올린다. 설치 NGO2.13.3/Unity6000.3.18f1은 유지한다. 이번 작업에서 모든 총기의 흔들림 수치·패턴·ADS 탄퍼짐은 변경하지 않는다. 느린 호흡/고정 반동 패턴은 제안 단계다.

## 2026-10-22 Alt 조작·LAN 방 목록·발사 시점 추종 (현재 규칙, 프로토콜48)

- 서버 연결 승인에서 방 ID·비밀번호 proof·닉네임·경기 단계·정원을 검증한 뒤 좌석/플레이어를 생성한다. 검색에는 비밀번호/proof를 보내지 않으며 응답 nonce/프로토콜/길이/주소를 검사한다. 접속 proof는 방 ID와 비밀번호의 SHA256이며 암호화 통신/계정 인증을 제공하는 방식은 아니다. 잘못된 비밀번호/진행 중 참가 거절은 좌석을 차지하지 않는다. 방 종료/실패/오브젝트 파괴 시 검색 소켓을 정리한다.
- 격발/총구 섬광 중에도 렌더 총기는 현재 시선과 현재 ADS 위치를 따른다. 이미 발사한 탄환의 원점/방향/난수 시드와 서버 피격 판정은 발사 당시 값으로 유지한다. 카메라 회전이 날아가는 탄을 꺾지 않는다. 무기 흔들림/피해/행동 규칙은 변경하지 않는다.
